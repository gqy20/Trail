# Trail

把 Chrome 标签页分组记录成一次可保存、可回看、可继续整理的研究轨迹。

## 使用流程

1. 在 Chrome 中打开一组调研页面，最好先放进同一个 Tab Group。
2. 打开 Trail popup，确认记录名称。
3. 点击“开始记录”。
4. 正常浏览、选中、复制和点击资料链接。
5. 点击“生成文档”，Trail 会保存本次研究记录并生成 Markdown。
6. 在研究文档页补充调研目标，查看来源、关注片段和折叠的调研路径。
7. 需要时编辑、保存、复制或导出 Markdown；准备接入 AI 时可导出“AI 输入”JSON。

## 交互捕获

Trail 只在录制期间捕获普通网页中的交互信号，不读取系统剪贴板，也不会记录输入框、文本域或可编辑区域中的内容。

当前支持：

- 复制捕获：用户在网页内选中文本并复制后，保存为“已复制”片段。
- 稳定选中：用户选中文本并停留片刻后，保存为“仅选中”关注片段。
- 复制升级：如果用户先选中、随后复制同一段文本，Trail 会把原片段升级为“已复制”，避免重复记录。
- 点击路径：用户点击搜索结果、外链、文档目录、GitHub 或下载链接后，保存为调研路径。
- 来源分级：Trail 会根据停留、选中、复制、链接点击和回访次数，粗略区分核心来源、参考来源和过渡页面。
- 上下文记录：可记录页面标题、URL、domain、章节标题、附近文本和大致页面位置。
- 片段治理：支持类型识别、重复复制合并、域名排除和可选自动脱敏。

相关开关在 popup 的“交互捕获”面板中：

- 记录网页复制
- 记录稳定选中
- 记录链接点击
- 保留来源上下文
- 复制后轻提示
- 合并重复片段
- 自动脱敏
- 不记录当前域名

自动脱敏默认关闭；开启后会在写入 `chrome.storage.local` 前隐藏常见邮箱、token、密钥和 API key 形态。

## 保存与导出

- 结构化记录保存在扩展自己的 `chrome.storage.local` 中，这是当前的事实数据源。
- 研究文档页的“保存”会把人工编辑后的 Markdown 写回本地记录。
- “导出”会下载 Markdown 文件，并记录最近导出的文件名和时间。
- “AI 输入”会导出版本化的 `ResearchReportInput` JSON，包含调研目标、来源、关注片段、点击路径和计数摘要。

下一阶段如果需要稳定写入 Obsidian、指定本地目录或团队知识库，可以在当前数据结构上增加本地文件夹授权或云端同步，而不改变采集逻辑。

## AI 接入准备

当前版本还没有直接调用 AI。接入前先做这些准备：

- 用 `ResearchReportInput` 作为模型输入契约，而不是直接把 UI 或整篇 Markdown 丢给模型。
- 给来源、证据片段和点击路径生成稳定 ID，方便模型输出引用。
- 控制输入长度，片段和上下文会做裁剪，避免无边界发送网页内容。
- 保留调研目标字段，让模型知道“这次要回答什么问题”。
- 继续保留人工编辑的 Markdown，AI 失败时仍然可以使用规则生成和手动整理。
- 后续真正接模型时应通过自有后端调用，不把 API key 放进扩展。

## Browser Tool

项目包含一个与研究记录核心解耦的声明式浏览器工具运行时。它可以在用户已登录的普通网页中执行受限的填写、点击、等待、翻页和 DOM 提取工作流，适合后续接入知网、Web of Science 等网页检索平台。

- 工具使用 YAML 定义，后台和 content script 都不执行 YAML 中的任意 JavaScript。
- 支持域名与 URL 匹配、参数模板、有限循环、结构化字段提取和内置转换。
- 工具可在 YAML 中声明独立的展示契约，工作区标题、输入、参数布局、结果名称和字段顺序不写入 Trail 核心。
- 批量输入支持直接放置多条检索词，也可由 YAML 启用多词组组合器，按 AND/OR 等平台允许的连接符生成并预览检索式。
- 结果可以由 YAML 声明详情页全文资源，用户勾选后按 PDF/CAJ 等格式串行下载；验证码、登录和权限页面会暂停处理。
- Side Panel 的“队列”可导入独立文献 CSV，识别 `title`、`doi`、`pdf_url`、`download_url`、`decision`，按 DOI/题名去重并持久化处理状态；全文解析复用浏览器登录态，支持设置 1–4 个并行任务和运行中暂停/继续，未发现 PDF 的记录保留为待检索或需人工处理。
- 全文下载优先在文章页上下文触发，以保留 Cookie、Referer 和站点生成的临时地址；Wiley 阅读器、EDP/Agronomy PDF入口和 ASHS 内嵌阅读器有独立解析分支，HTML响应不会再被记录为 PDF。
- `browser-tools/catalog.yml` 统一登记随插件安装的内置工具，首次安装或升级时会批量初始化，同时保护用户自定义版本。
- 密码框始终禁止填写；登录、验证码和机构认证应通过 `pause_for_user` 交还用户处理。
- 后台在执行前会重新校验 YAML，并要求显式的用户启动标记。

定义格式、调用方式和示例位于 [`browser-tools/`](browser-tools/README.md)。popup 中的扳手入口会在当前网页旁打开 Chrome Side Panel，可导入或更新 YAML、填写参数，也可粘贴或从 TXT/CSV 导入一批检索词，逐词检索、提取并汇总带 `_query` 来源列的结果，再将当前或历史结果导出为 CSV/JSON；“队列”页负责跨来源文献清单和下载状态，不把具体站点规则写进核心。验证码、登录或权限受限项目会保留入口供用户处理后重试。不支持 Side Panel 的浏览器会回退到独立页面。

## 每日签到

Side Panel 新增“签到”入口，内置科研通、GLaDOS One（glados.one）、GLaDOS Rocks（glados.rocks）三个独立签到项。它们复用各自域名的浏览器登录状态，不需要粘贴 Cookie 或保存密码。

1. 构建并重新加载 Trail 后，打开侧边栏的“签到”；旧安装可在设置中同步内置工具。
2. 使用“打开网站”完成登录，再点“立即签到”验证。
3. 按需开启各项“每日自动签到”，默认时间为北京时间 09:00，默认关闭。

Chrome 运行时每 5 分钟检查到期任务，浏览器启动后会补跑当天到期的任务。不会唤醒关机或休眠的电脑。完成结果按域名工具和当地日期分别保存；同一域名切换账户后，当天仍沿用该工具的完成记录，当前不支持同域名多账户。

自动运行只接受用户开启时的工具版本；YAML 改变后会暂停并要求重新开启。网络加载失败最多每天尝试 3 次，间隔至少 30 分钟。登录、验证码、返回结果不明或后台中断时保留工作页面，点击“打开网站”处理后重试。成功后只关闭本次创建的工作标签页。

验证命令：`npx playwright install chromium`（首次安装浏览器），然后 `npm run test:checkin`。测试使用隔离扩展配置及页面夹具，不使用真实账户；可通过 `TRAIL_TEST_CHROMIUM` 指定已有 Chromium 可执行文件。

## 当前边界

- 暂不保存完整网页正文，只保存标签页、交互事件和轻量上下文。
- `chrome://`、扩展页面、地址栏和非网页应用中的复制不会被捕获。
- 来源分级是启发式判断，用来辅助排序，不代表严格可信度评级。
- “AI 输入”只是本地导出的结构化材料，还不是自动总结。

## 本地开发

```bash
npm install
npm run build
```

构建完成后，在 Chrome 扩展管理页打开“开发者模式”，选择“加载已解压的扩展程序”，加载生成的 `dist/` 目录。

测试交互捕获时，需要刷新扩展和目标网页：

1. 运行 `npm run build`。
2. 在 `chrome://extensions` 中重新加载 Trail。
3. 刷新需要测试的网页，让 `content.js` 重新注入。
4. 点击 Trail popup 中的“开始记录”。
5. 在当前录制范围内选中或复制网页文本。
6. 停止记录后，在研究文档页查看“关注片段”。

## 发布

发布使用 GitHub Actions，推送 `v*` 标签会自动构建 Chrome 扩展并创建 GitHub Release：

```bash
git tag v0.1.0
git push origin v0.1.0
```

发布前需要同步以下版本号：

- `package.json`
- `public/manifest.json`
- `CHANGELOG.md` 中的 `## [x.y.z]`

Release 产物：

- `trail_v0.1.0_chrome.zip`
- `checksums.txt`

zip 内部直接包含 `manifest.json`、`entries/`、JS、assets 和 icons，可用于 Chrome Web Store 上传或手动分发。
